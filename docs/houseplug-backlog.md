## Cross-cutting acceptance suite

Protect existing browse/auth/listing submission/roommate own-profile flows. New checks must establish behavior rather than mirror implementation. Mandatory risk cases: unknown fee stays unknown; occupancy 1 cannot split; profile identity cannot become physical inspection; rented/stale inventory excluded; no false confirmed appointment; cross-user private data denied; webhook duplicate/failure recovery; indexable URLs correct; no demo listings; 320–1280px usable controls. Validate raw API/RLS, not only UI.

## Data decisions required before schema tickets

Never automatically backfill unknown mandatory fees to zero, historic profile verification to property inspection, old active rows to recently confirmed, or occupancy>=2 to owner permission. Use nullable/additive contracts, quarantine incomplete promotions, recover actual schema, create reviewed operator backfill. Existing IDs and functioning public pages stay compatible. No production migrations in this discovery step.
